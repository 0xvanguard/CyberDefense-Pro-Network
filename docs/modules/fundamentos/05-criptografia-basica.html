05 — Criptografía básica

Conceptos esenciales de hash, cifrado simétrico y asimétrico. Sin meterte fórmulas.

1. Las 3 cosas que protege

  • Confidencialidad — nadie más lee.
  • Integridad — nadie alteró sin permiso.
  • Autenticidad — quién lo envió y que no se alteró.

2. Hash — la huella digital de un dato

Un hash toma cualquier cantidad de datos y devuelve una cadena fija de tamaño.

"hola"      → 4d...uo  (SHA-256)
"hola."     → d8...xq  (distinto aunque cambies 1 carácter)

Propiedades: Determinista, rápido, irreversible (del hash no recuperas la entrada), resistente a colisiones.

Algoritmos comunes

AlgoritmoTamañoEstado
MD5128 bits❌ Roto. Solo legacy.
SHA-1160 bits❌ Roto.
SHA-256256 bits✅ Estándar.
SHA-3256+✅ Más nuevo.
BLAKE2variable✅ Muy rápido.
Error común

Usar SHA-256 directamente sobre la contraseña. Correcto es usar un algoritmo lento y con sal: bcrypt, scrypt, Argon2.

3. Cifrado simétrico — misma clave

   ┌──── mensaje ────┐
        clave K
   └──── mismo K ────┘
   cifrado         descifrado

Algoritmos recomendados: AES-256-GCM (estándar), ChaCha20-Poly1305 (alternativa moderna).

Problema: ¿cómo compartes la clave sin que la intercepten?

4. Cifrado asimétrico — par de claves

  Clave pública (cualquiera la ve)
            ↓ cifra
        mensaje cifrado
            ↓ descifra con clave privada
        mensaje original

  Clave privada (solo tú)

Algoritmos: RSA (clásico), ECC/Curve25519 (mod), Ed25519 (firmas).

Usos: cifrar (solo receptor descifra), firmar (cualquiera verifica), HTTPS acuerda clave simétrica.

5. Firmas digitales

  1. Hash del documento.
  2. Cifras el hash con tu clave privada → firma.
  3. Adjuntas firma al documento.
  4. Receptor descifra la firma con tu pública → compara con hash del documento. Si coinciden: íntegro y auténtico.

6. Certificados y PKI

Un certificado digital (X.509) ata una identidad (dominio) a una clave pública. Lo firma una CA de confianza (Let's Encrypt, DigiCert).

# Ver el certificado de una web
openssl s_client -connect github.com:443 -showcerts

# Extraer info
echo | openssl s_client -connect github.com:443 2>/dev/null | openssl x509 -noout -subject -issuer -dates

7. HTTPS — qué pasa realmente

  1. Tu navegador → "Hola, quiero HTTPS".
  2. Servidor → "Aquí mi certificado".
  3. Tu navegador → verifica la cadena.
  4. Ambos acuerdan un algoritmo y generan una clave simétrica (TLS handshake).
  5. A partir de ahí, todo va cifrado con AES.
